# 登录时间变化后的身份复核

开源版与集团版使用同一流程。首次启用先用当前 DWS 登录核对精确 profile、公共账号在消息中的 selfId 和登录时间基线 expectedLoginAt。之后每次发现时间变化，验证通过就继续本次轮询；只在不能确认时显示中文暂停提示，下一轮会再检查。不要清空时间字段、切换默认 profile、重置游标或要求用户重发。

- 没有登记单聊证据时，可用同一 profile 的 contact user get-self，必须返回与 selfId 同命名空间且一致的 openDingtalkId；组织名、clientId、企业内部 userId 或昵称均不够。
- 对没有通讯录权限的账号，管理员可在原生 Source 配置 JSON 中添加可选的 identityWitness。取自**已人工核实过的、原公共账号主动发给已知对端的历史一对一投递成功回执**，不要从当前候选消息、群聊、转发或任意可见消息中自动登记。无需为验证发送新消息。示例：

```json
{"identityWitness":{"peerId":"<已核对的另一方 openDingtalkId>","conversationId":"<该单聊的会话 ID>","messageId":"<已确认送达的消息 ID>","sentAt":"2026-11-07T00:08:16+08:00"}}
```

在原有 config 上合并这一字段，保留 profile、selfId、群、收发开关、expectedLoginAt 和其他字段，按 revision 保存。复核通过当前账号**与该对端的单聊历史**查询指定发送时间附近最多 5 条消息；校验原会话、消息 ID、发送时间及原 senderId。按消息 ID 的全局读取或查询旧发送任务不能单独证明当前是谁。只缓存已核验时间，不缓存单聊正文、令牌或密码。配置身份或证据变更后不得复用此前缓存。若证据已不可读且不能取得可信的当前账号信息，请管理员重新核对真实登录身份并登记有效证据。

**仅在排查身份恢复时**：记录暂停前的群游标（包括续页时间）、已有群消息 ID 对应的 Trigger 和工单。恢复后以稳定消息 ID 对照暂停期间的 DWS 群历史：依策略应该接收的消息各有一个 Trigger，闲聊/忽略样本不能产生工单；已接单消息仍关联原工单。至少再观察两次成功游标推进并复核数量。不能用最近一条消息的时间、群消息总数或单独一个 ready 状态替代这些核对。身份不符或证据不足时，游标应保持原值，不产生新 Trigger，也不发送测试消息。
